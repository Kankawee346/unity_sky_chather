# สถานะเทียบใบเกณฑ์คะแนน Cyber

## ตัวเกมและโปรแกรม

| เกณฑ์ | สถานะ |
| --- | --- |
| เกมรับของตก 1–3 ชนิด | เวอร์ชันส่งงานสุ่มเหรียญทอง 4 คะแนน เหรียญแดง 10 คะแนน และถังน้ำมัน 0 คะแนนพร้อมเติมพลัง 20 |
| ความยาก 3 ระดับ | Easy/Normal/Hard เปลี่ยนความเร็วและความถี่ตก ระดับที่ส่ง Firebase คือ 1/2/3 ตามที่เลือก |
| คำชม Combo | รับติดกัน 2/3/4/5 ครั้งมีข้อความตามระดับ |
| เซนเซอร์ 2 โหมด | FSR ซ้าย/ขวา 2 ตัว หรือจอยสติก 1 ตัว เลือกโหมดบนหน้าเริ่มเกม ใช้ ESP32-S3 ตัวเดียว |
| MQTT ความหน่วงต่ำ | รับค่าจากตัวเชื่อมเดิมผ่าน `/controller/latest` และค้างค่าไม่เกิน 0.35 วินาทีเมื่อขาดการเชื่อมต่อ |
| Firebase | บันทึกชื่อผู้เล่น คะแนน ระดับ เวลา จำนวนรับ/เห็น และจำนวนครั้งที่เล่น; อ่านสถิติแยกผู้เล่นได้ผ่าน `/rounds/analytics` |
| จอ LCD I2C 16×2 | เฟิร์มแวร์เปิดใช้แล้ว แสดงคะแนน เวลา ระดับ และโหมด; หลังต่อจริงต้องปรับคอนทราสต์ให้อ่านชัด |
| Google Sheets | Bridge ซิงก์ผลจาก Firebase ไปแท็บ `CatchLab Rounds`; Dashboard ในชีตที่ใช้งานจริงสรุปผลตามรอบใหม่ |

ทดสอบเว็บด้วยคีย์บอร์ดแล้ว: กดเริ่ม เล่นครบ 30 วินาที รับของ/คอมโบและหน้าจบรอบได้จริง มีผลรอบจริงใน Firebase และ Google Sheets

## งานที่ต้องทำก่อนส่งเพื่อป้องกันคะแนนตก

1. หลังย้ายสายจอยจาก VRx ไป VRy ให้อัปโหลด `CatchController.ino` รุ่นล่าสุด แล้วทดสอบทิศซ้าย/ขวาใน **เวอร์ชัน UI เพื่อน** จริง หากกลับด้านให้เปลี่ยน `JoystickYHighMeansLeft` เป็น `false` และอัปโหลดใหม่
2. ถ่ายวิดีโอหลักฐานการกด FSR ซ้าย/ขวารัว ๆ การสลับโหมดจอย การส่ง MQTT และข้อความ LCD ที่อ่านชัด
3. จัดทำโปสเตอร์ A1 และวิดีโอสาธิตแนวตั้ง Full HD 60 fps ไม่เกิน 3 นาที ตามใบเกณฑ์
4. แนบ `code.zip` ซึ่งมีซอร์ส `CatchLabFriend`, `ControllerBridge`, `Firmware`, Web Build, ไลบรารี Arduino และคู่มือติดตั้ง/ใช้งาน โดยไม่นำ `.env.local` หรือข้อมูลลับใน `Settings.h` ไปเผยแพร่
5. ยืนยันกับอาจารย์ถ้าประเมินคำว่า ESP32 แบบ 38 pin หรือจำนวนเซนเซอร์ต่อโหมดอย่างเคร่งครัด เพราะระบบนี้ใช้ ESP32-S3 หนึ่งบอร์ด, FSR 2 ตัว และจอย 1 ตัว

UI เก่าอยู่ที่ `../CatchLab` และไฟล์สำรอง `../Design/CurrentUI/CatchLab-Original-Source.zip` ไม่ได้ถูกแทนที่
