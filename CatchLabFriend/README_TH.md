# CatchLab เวอร์ชัน UI เพื่อน

โปรเจกต์นี้แยกจาก `../CatchLab` โดยสิ้นเชิง ฉาก ภาพ เครื่องบิน และเมนูของเพื่อนอยู่ที่ `Assets/Scenes/SampleScene.unity` ส่วนโปรเจกต์เดิมยังเปิดและสร้าง Web ได้ตามเดิม

## เปิดเล่น

1. เปิด `CatchLabFriend` ใน Unity 6.5.2f1 แล้วเปิด `Assets/Scenes/SampleScene.unity` กด Play เพื่อทดลองด้วย A/D หรือลูกศร
2. เลือก Easy, Normal หรือ Hard, เลือกฉาก, เลือกภาษา `EN`/`TH` และเลือก `FSR 2` หรือ `JOYSTICK` ก่อนกด Play
3. ถ้าจะใช้เซนเซอร์หรือเล่นบนเว็บ ให้ปิดตัวเชื่อมเดิมด้วย `Ctrl+C` ก่อน แล้วเปิดตัวเชื่อมในโฟลเดอร์ `../ControllerBridge` ด้วย `npm.cmd run friend` เพียงหน้าต่างเดียว เปิด `http://127.0.0.1:8787/` อย่าเปิด `npm.cmd start` พร้อมกันเพราะใช้พอร์ตเดียวกัน
4. ถ้าไม่มี ESP32 ให้ใช้ `npm.cmd run friend-keyboard` และเล่นด้วยคีย์บอร์ด
5. เมื่อต้องสร้างเว็บใหม่: เมนู Unity `CatchLab Friend > Build Web` จะออกที่ `Build/Web`

ถ้านำไฟล์ ZIP ซอร์สไปเปิดในเครื่องอื่น: แตก ZIP ให้โฟลเดอร์ `CatchLabFriend`, `ControllerBridge` และ `Firmware` อยู่ระดับเดียวกัน เปิดโปรเจกต์ `CatchLabFriend` ใน Unity แล้วสร้างเว็บตามข้อ 5 จากนั้นเปิด terminal ที่ `ControllerBridge` และรัน `npm.cmd ci` หนึ่งครั้ง คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ที่อยู่คอม รหัส MQTT, Firebase project ID และตำแหน่งไฟล์ service account ของตนเอง หากใช้ ESP32 ให้คัดลอก `Settings.example.h` เป็น `Settings.h` และใส่ค่าให้ตรงกัน อย่านำสองไฟล์ที่มีรหัสผ่านนี้ไปเผยแพร่

เมื่อกลับมาเล่นด้วย ESP32-S3 ให้ต่อคอมกับ ESP เข้ากับ Wi-Fi เดียวกัน ตรวจว่าที่อยู่คอมตรงกับ `BrokerHost` ใน `../Firmware/CatchController/Settings.h` และอัปโหลดเฟิร์มแวร์ก่อนเปิดเกม ถ้าเปลี่ยนเครือข่ายจน IP เปลี่ยน ให้แก้ `BrokerHost` แล้วอัปโหลดใหม่

## ระบบเกม

- FSR ซ้าย/ขวา 2 ตัวหรือจอยสติก 1 ตัว เลือกใช้ทีละโหมด ค่าที่อีกโหมดส่งมาจะไม่ขยับผู้เล่น จอยใช้ขา VRy ต่อเข้า GPIO6 ของ ESP32-S3 เพื่อเลื่อนซ้ายขวา ส่วน VRx ไม่ใช้
- ของที่ตก 3 ชนิด: เหรียญทอง 4 คะแนน, เหรียญแดง 10 คะแนน, ถังน้ำมัน 0 คะแนนพร้อมเติมพลัง 20 ตามค่าของเพื่อน (เก็บ prefab สิ่งกีดขวางของเพื่อนไว้ แต่ไม่สุ่มในโหมดส่งงานเพื่อให้ตรงจำนวนชนิดตามเกณฑ์)
- Combo รับติดกัน 2/3/4/5 แสดงคำชม; พลาดแล้วเริ่มใหม่
- แต่ละรอบ 30 วินาที ระดับความยากกำหนดความเร็วและความถี่การตก; เกจ HP ลดเมื่อพลาด แต่ยังเล่นจนหมดเวลา
- เมื่อจบรอบ ระบบส่งคะแนน เวลา ระดับ จำนวนที่เห็น/รับได้ และชื่อผู้เล่นไปยังตัวเชื่อมเพื่อบันทึก Firebase
- ตัวเชื่อมส่งสถานะคะแนน เวลา ระดับ และโหมดกลับไป ESP32 สำหรับ LCD 16×2 เมื่อเชื่อมอุปกรณ์

## ตรวจผล Firebase

เปิด `http://127.0.0.1:8787/rounds/analytics?playerId=ชื่อผู้เล่น` หลังเล่นครบหนึ่งรอบ ต้องตั้งค่า Firebase ใน `ControllerBridge/.env.local` เช่นเดิม ชื่อผู้เล่นใน URL ต้องเข้ารหัส URL หากมีภาษาไทยหรือช่องว่าง

## ดูผลใน Google Sheets

ตัวเชื่อมเกมยังบันทึก Firebase ตามเดิม และซิงก์ผลทุกคนทุกระดับไปยังแท็บ `CatchLab Rounds` ใน Google Sheet ที่ระบุด้วย `CATCHLAB_SHEET_ID` ใน `ControllerBridge/.env.local` แท็บนี้มีวันที่เวลาไทย ชื่อผู้เล่น จำนวนครั้งที่เล่น ระดับ คะแนน จำนวนที่รับได้/ตกทั้งหมด ความแม่นยำ และเวลาเล่น แท็บอื่นในไฟล์ชีตไม่ถูกแก้ไข

การเปิดใช้ครั้งแรก: ใช้บัญชี Google ที่เป็นเจ้าของโปรเจกต์ Firebase เปิด Google Sheets API ใน Google Cloud โปรเจกต์เดียวกัน จากนั้นเปิดไฟล์ Google Sheet แล้วแชร์สิทธิ์ Editor ให้บัญชีบริการที่อยู่ในไฟล์ JSON ของ `GOOGLE_APPLICATION_CREDENTIALS` (ดูค่า `client_email` โดยไม่ต้องส่งไฟล์ JSON ให้ผู้อื่น) คัดลอกส่วนรหัสระหว่าง `/d/` กับ `/edit` จากลิงก์ชีตมาใส่ `CATCHLAB_SHEET_ID` แล้วที่โฟลเดอร์ `ControllerBridge` รัน `npm.cmd run sheets-sync` หนึ่งครั้งเพื่อเติมรอบเก่าจาก Firebase รอบใหม่จะซิงก์อัตโนมัติเมื่อเล่นจบและตัวเชื่อมเกมกำลังทำงาน ถ้า Google Sheets ใช้ไม่ได้ Firebase จะยังบันทึกตามปกติ และตัวเชื่อมจะแสดงข้อผิดพลาดในหน้าต่างคำสั่ง

## ข้อจำกัดขณะนี้

- หลังเปลี่ยนสายจอยจาก VRx เป็น VRy ต้องอัปโหลดเฟิร์มแวร์รุ่นล่าสุด และทดสอบทิศทางซ้าย/ขวาอีกครั้งกับอุปกรณ์จริง
- Ranking ในฉากของเพื่อนยังอ่านจากเครื่องที่เล่น (PlayerPrefs); ผลรอบและสถิติข้ามเครื่องอ่านจาก Firebase ผ่าน endpoint ด้านบน
- งานส่งอาจารย์ยังต้องมีโปสเตอร์ วิดีโอสาธิต และเอกสารติดตั้งตามใบเกณฑ์
