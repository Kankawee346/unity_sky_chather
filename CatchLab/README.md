# Catch Lab

ต้นแบบเกมรับของสำหรับวิชา Cyber-Physical System and Sensor

## เปิดใน Unity

1. ใน Unity Hub เลือก Add > Add project from disk แล้วเลือกโฟลเดอร์ CatchLab
2. เปิดด้วย Unity 6000.5.2f1 แล้วเปิดฉาก Assets/Scenes/SampleScene.unity
3. กด Play เกมจะเปิดเมนูอัศวิน เลือกระดับและโหมดควบคุมก่อนเริ่มรอบ 30 วินาที

## ทดสอบใน Editor

- เลือก FSR แล้วกด A หรือ D เพื่อจำลองมือซ้ายหรือขวา
- เลือก Joystick แล้วกดลูกศรซ้ายหรือขวา ลองกด A หรือ D เพื่อเช็กว่าโหมด Joystick ไม่รับคำสั่งชุด FSR
- กดคำสั่งสองข้างพร้อมกัน ตะกร้าควรหยุด
- Easy, Medium และ Hard เล่นรอบละ 30 วินาที ของตกเร็ว 145 / 275 / 425 หน่วยต่อวินาที ตามลำดับ กลางไหลเฉียงเล็กน้อย ยากส่ายซ้ายขวา
- เหรียญ +1, อัญมณี +2, ขวดยา +3 คะแนน รับพลาดเสียหัวใจ 1 ดวง แต่เล่นต่อจนครบเวลา
- รับของติดกันเพื่อทดสอบคำชมที่ 2, 3, 4 และ 5 ครั้ง พลาดหนึ่งครั้งจะเริ่มนับใหม่

## ต่อฮาร์ดแวร์ในขั้นถัดไป

ต้นแบบใช้ ESP32-S3 หนึ่งบอร์ดอ่าน FSR สองตัวกับ Joystick หนึ่งตัว เลือกรุ่นบอร์ด ESP32-S3 ใน Arduino IDE
ทั้ง SensorCheck และ CatchController ใช้ FSR ซ้ายที่ GPIO4, FSR ขวาที่ GPIO5 และ **VRy** ของ Joystick ที่ GPIO6 โดยใช้ GND ร่วมกัน ขา VRx ไม่ใช้
ใช้ไฟ 3.3 V กับจอยถ้าโมดูลรองรับ และอย่าป้อนสัญญาณ 5 V เข้า GPIO
โค้ด SensorCheck แสดง `fsr_left_raw,fsr_right_raw,joystick_y_raw` ที่ 115200 baud
FSR เริ่มกดที่ 500 ขึ้นไปและปล่อยเมื่อต่ำกว่า 350 จอยแกน Y อยู่กลางที่ 1720–2220 ค่าเหนือช่วงคือซ้ายและค่าต่ำกว่าช่วงคือขวาตามค่าตั้งต้น ถ้าทิศทางกลับกันให้เปลี่ยน `JoystickYHighMeansLeft` ใน CatchController เป็น `false`
โหมด FSR ใช้แผ่นกดซ้ายและขวาแยกกัน โหมด Joystick ใช้แกน Y ของจอยตัวเดียวเป็นคำสั่งเลื่อนซ้ายขวาและให้ตำแหน่งกลางหยุดตะกร้า
ชั้นรับข้อมูลในเกมคือ CatchGame.ReceiveSensorSample(leftFsrPressed, rightFsrPressed, joystickDirection)
ให้ตัวเชื่อมเรียกบนเธรดหลักด้วยค่าที่คาลิเบรตแล้ว โดยส่งทิศจอยเป็น -1 (ซ้าย), 0 (กลาง) หรือ 1 (ขวา)
เกมเลือกเซนเซอร์ตามโหมดและทิ้งค่าค้างหลังขาดข้อมูล 0.35 วินาที

## ทดสอบควบคุม Unity ด้วย MQTT

1. ใช้เฟิร์มแวร์ `Firmware/CatchController/CatchController.ino` สำหรับรอบ Wi-Fi ต่อ FSR ซ้ายที่ GPIO4, FSR ขวาที่ GPIO5 และ VRy ของจอยที่ GPIO6 ทั้งสามขาเป็น ADC1 โค้ด SensorCheck ใช้ขาชุดเดียวกันสำหรับทดสอบผ่าน Serial
2. ให้คอมและ ESP32 อยู่เครือข่ายเดียวกัน หา IPv4 ของคอมจาก `ipconfig` คัดลอก `Settings.example.h` เป็น `Settings.h` ในโฟลเดอร์ `Firmware/CatchController` ถ้ายังไม่มี แล้วใส่ชื่อและรหัส Wi-Fi, IP คอม และตั้งรหัส MQTT ในไฟล์นี้ อย่าส่งไฟล์ Settings.h ที่มีรหัสจริง
3. เปิด PowerShell ในโฟลเดอร์ `ControllerBridge` แล้วรันคำสั่งด้านล่าง โปรแกรมอ่าน IP และรหัส MQTT จาก Settings.h โดยตรง ใช้บนเครือข่ายส่วนตัวสำหรับทดสอบ เนื่องจาก MQTT พอร์ต 1883 ไม่มี TLS

   ```powershell
   npm.cmd install
   npm.cmd start
   ```

4. ติดตั้งไลบรารี PubSubClient จาก Arduino Library Manager แล้วเปิด CatchController.ino เลือก ESP32S3 Dev Module และอัปโหลด
5. เช็ก Serial Monitor ที่ 9600 ว่าขึ้น `MQTT connected` แล้วลองเปิด `http://127.0.0.1:8787/controller/latest` ขณะบอร์ดออนไลน์ จะเห็นข้อมูล เช่น `0,0,0` ถ้าไม่เห็น ให้เช็ก IP, รหัส MQTT และว่าไฟร์วอลล์อนุญาต TCP 1883 บนเครือข่ายส่วนตัว
6. เปิด SampleScene แล้วกด Play ทดสอบ FSR ซ้ายและขวา จากนั้นเลือก Joystick และลองโยกทั้งสองทาง เมื่อข้อมูลหยุดมา คำสั่งจะหมดอายุอัตโนมัติ

## จอ LCD I2C 16×2

เกมส่งคะแนน เวลา ระดับ โหมด และสถานะไปที่ `/game/status` บน Bridge และ Bridge ส่งต่อหัวข้อ MQTT `catchlab/game/status` ให้ ESP32-S3 จอบรรทัดแรกแสดงคะแนน/เวลาคงเหลือ บรรทัดสองแสดงระดับ/โหมด/READY, PLAY, PAUSE หรือ END ปรับเฉพาะตัวอักษรที่เปลี่ยนในจอ เพื่อลดการหน่วงของการอ่าน FSR

ก่อนต่อจริง ให้ตรวจว่าบอร์ด LCD I2C ใช้ไฟและตัวต้านทานดึงสัญญาณที่ปลอดภัยกับขา 3.3 V ของ ESP32-S3 โดยเฉพาะบอร์ด LCD ที่จ่ายไฟ 5 V อย่าต่อ SDA/SCL ที่ถูกดึงขึ้น 5 V เข้าบอร์ดตรง ๆ ให้ใช้วงจรแปลงระดับสัญญาณหากจำเป็น ต่อ GND ร่วมกัน แล้วเลือกขา SDA/SCL ที่มีอยู่จริงบนบอร์ด ใน `Firmware/CatchController/LcdConfig.h` ตั้งค่าเริ่มต้น SDA=GPIO8, SCL=GPIO9 และเปลี่ยนให้ตรงกับการต่อจริง

ติดตั้งไลบรารี `hd44780` ของ Bill Perry ใน Arduino Library Manager จากนั้นเปลี่ยน `CATCHLAB_LCD_ENABLED` เป็น `1` ใน `LcdConfig.h` แล้วอัปโหลดอีกครั้ง ตัวโปรแกรมค้นหาที่อยู่ I2C ของจออัตโนมัติ ถ้าจอไม่พบ เกมและเซนเซอร์ยังทำงานได้ ตรวจ Serial Monitor ที่ 9600 ถ้าขึ้น `LCD not detected` ให้ตรวจไฟ ขา และวงจร I2C จอใช้ตัวอักษรอังกฤษแบบย่อเพื่อให้อ่านได้ครบ 16 ช่อง

ดูค่าอะนาล็อกขณะทดสอบได้โดยส่ง `r` ใน Serial Monitor ที่ 9600 เฟิร์มแวร์จะแสดง `fsr_left_raw,fsr_right_raw,joystick_y_raw` ทุก 50 มิลลิวินาที ส่ง `r` ซ้ำเพื่อหยุดแสดง

เฟิร์มแวร์ MQTT อ่านเซนเซอร์ทุก 5 มิลลิวินาที ส่งเมื่อคำสั่งเปลี่ยนและยืนยันสถานะทุก 50 มิลลิวินาที ตัวรับเก็บการเปลี่ยนสถานะช่วงสั้น ๆ ให้ Unity อ่านเรียงลำดับ และตอบทันทีเมื่อมีค่าใหม่ FSR เริ่มกดที่ 500 ขึ้นไปและปล่อยเมื่อต่ำกว่า 350 ส่วนเกณฑ์ของ SensorCheck ใช้สำหรับทดสอบแยก

## ทดสอบเกมบนเว็บบนคอมเครื่องนี้

1. ใน Unity Hub เปิด Installs แล้วเพิ่ม Web Build Support ให้ Editor รุ่น 6000.5.2f1 ถ้ายังไม่มี
2. เปิด CatchLab ใน Unity แล้วเลือก CatchLab → Build Web Demo โปรเจกต์จะสร้างไฟล์ใน `CatchLab/Build/Web`
3. ถ้าตัวรับ MQTT เปิดอยู่ ให้กด Ctrl+C และรัน `npm.cmd start` ใหม่จาก ControllerBridge
4. เปิด `http://127.0.0.1:8787/` ในเบราว์เซอร์ เกมกับเส้นทาง `/controller/latest` ใช้พอร์ตเดียวกัน ลอง FSR ทั้งสองข้างและโหมด Joystick

สำหรับเปิดเกมจากเครื่องอื่น ต้องตั้งเว็บเซิร์ฟเวอร์ HTTPS ให้บริการไฟล์ Web Build และส่งต่อ `/controller/latest` ไปยัง bridge ที่ `127.0.0.1:8787` บนเครื่องที่รัน bridge

## กลับมาเปิดเล่นหลังปิดฮอตสปอต

1. เปิดฮอตสปอต iPhone แล้วให้คอมต่อ Wi-Fi เดิม เปิด Command Prompt แล้วพิมพ์ `ipconfig` ดู IPv4 ในหัวข้อ Wi-Fi เทียบกับ `BrokerHost` ใน `Firmware/CatchController/Settings.h`
2. ถ้า IP กับชื่อและรหัส Wi-Fi เหมือนเดิม ให้ใช้เฟิร์มแวร์ที่อยู่บน ESP32 ได้เลย ถ้า IP เปลี่ยน ให้แก้เฉพาะ `BrokerHost` เป็น IPv4 ของคอม ถ้าเปลี่ยน Wi-Fi ให้แก้ `WifiName` และ `WifiPassword` ด้วย แล้วอัปโหลด `CatchController.ino` ใหม่
3. ใน Command Prompt เข้าโฟลเดอร์ `ControllerBridge` แล้วรัน `npm.cmd start` เปิดหน้าต่างไว้ ถ้ามีตัวรับเปิดอยู่แล้วและเพิ่งแก้ `Settings.h` ให้กด Ctrl+C แล้วเปิดใหม่เพื่อโหลดค่าใหม่
4. เสียบ ESP32 รอให้เชื่อมต่ออัตโนมัติ ถ้าต้องเช็ก ให้เปิด Serial Monitor ที่ 9600 แล้วดู `MQTT connected` หรือเปิด `http://127.0.0.1:8787/controller/latest` และเช็กว่ามีข้อมูล
5. เปิด `http://127.0.0.1:8787/` แล้วลอง FSR และจอย ใช้ Web Build ที่มีอยู่ได้ทันที สร้างใหม่เมื่อแก้เกมใน Unity

## ทดสอบด้วยคีย์บอร์ดและบันทึกผลลง Firebase

ในโฟลเดอร์ `ControllerBridge` รัน `npm.cmd run keyboard` เพื่อเปิดหน้าเว็บและตัวรับผลโดยไม่เปิด MQTT จึงไม่ต้องเสียบ ESP32 หรือต่อฮอตสปอตเดิม ถ้ามีตัวรับเปิดอยู่ ให้หยุดด้วย Ctrl+C ก่อน ใช้ A/D ในโหมด FSR หรือลูกศรในโหมด Joystick

สำหรับบันทึกผลจริง ให้สร้าง Cloud Firestore ใน Firebase Console และเตรียมข้อมูลรับรองของโปรเจกต์ตาม [คู่มือ Firebase Admin SDK](https://firebase.google.com/docs/admin/setup) เก็บไฟล์กุญแจไว้นอกโปรเจกต์ คำสั่ง `npm.cmd start` และ `npm.cmd run keyboard` จะโหลด `ControllerBridge/.env.local` ถ้ามี หรือจะตั้งค่าด้านล่างใน PowerShell ก่อนเปิดตัวรับก็ได้

```powershell
$env:CATCHLAB_FIREBASE_PROJECT_ID = 'your-firebase-project-id'
$env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\path\outside-project\service-account.json'
$env:CATCHLAB_PLAYER_ID = 'demo'
npm.cmd run keyboard
```

ใช้ `npm.cmd start` แทนเมื่อกลับมาทดสอบ ESP32 ด้วยค่าชุดเดียวกัน ตัวรับผลใช้สำหรับทดสอบบนเครื่องนี้ ถ้าจะเปิดให้ผู้เล่นจากเครื่องอื่นส่งผล ต้องเพิ่มการยืนยันตัวตนและแยกผู้เล่นก่อน

กด Play ใน Unity หรือ Build Web Demo ใหม่แล้วเปิดเกมในเบราว์เซอร์ เล่นให้ครบ 30 วินาที แล้วเปิด Firestore ดูที่ `players/demo/rounds` (ใช้รหัสที่ตั้งไว้แทน demo) ระบบบันทึกคะแนน ระดับ เวลาที่เล่น วันเวลาที่จบ จำนวนครั้งที่เล่น และจำนวนของที่รับได้เทียบกับจำนวนของที่ตกถึงตะกร้า

## ดูข้อมูลสำหรับกราฟแนวโน้ม

รีสตาร์ตตัวรับแล้วเปิด `http://127.0.0.1:8787/rounds/analytics` เพื่อดูข้อมูล JSON จาก 100 รอบล่าสุดของผู้เล่นที่ตั้งไว้ ประวัติเรียงตามครั้งที่เล่นและแยกเป็นสามระดับความยาก

- `history[].accuracyPercent` คือเปอร์เซ็นต์ของที่รับได้ในรอบนั้น รอบที่ไม่มีของตกถึงตะกร้าหรือไม่มีข้อมูลจำนวนของจะแสดง `null`
- `levels[].accuracyPercent` คิดจากยอดรวมของที่รับได้หารยอดรวมของที่ตกถึงตะกร้าในระดับนั้น
- `changePercentagePoints` คือส่วนต่างของอัตรารับสำเร็จระหว่างรอบแรกกับรอบล่าสุดที่มีข้อมูลของระดับนั้น ภายในช่วงข้อมูลที่อ่าน แสดง `null` หากมีข้อมูลเปรียบเทียบไม่ถึงสองรอบ
