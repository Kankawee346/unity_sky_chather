# ส่งให้เพื่อน: กล้อง Raspberry Pi → CYBER//DIVE

เพื่อนทำเฉพาะ Camera 3 → ตรวจผู้เล่นคนเดียว → จำแนกท่า → ส่ง MQTT ส่วนคอมทำเกมและ Bridge ภาพวิดีโอไม่จำเป็นต้องส่ง

## การเชื่อม

- Pi, ESP32 และคอมอยู่ Wi-Fi เดียวกัน
- คอมรัน `CyberDiveBridge` แทน Bridge เกมเก่า ปิดตัวเก่าก่อนเพราะใช้พอร์ต 1883/8787 เหมือนกัน
- MQTT broker: IPv4 Wi-Fi ของคอม, TCP 1883
- username `catchlab`; password ตรงกับ `.env.local` ของ Bridge และ firmware ESP32 ส่งรหัสให้กันส่วนตัว ห้ามใส่ใน Git หรือเอกสารส่งงาน
- Pi ใช้ client ID ไม่ซ้ำ ESP32 เช่น `pose-pi-1234`
- Publish topic `catchlab/pose`, qos=0, retain=false ประมาณ 10 ครั้ง/วินาที

## รูปแบบ v1 ที่ต้องส่ง

```json
{"v":1,"sessionId":"a-unique-id-per-start","seq":42,"gesture":"PARRY","active":true,"confidence":0.95}
```

- `sessionId`: UUID แบบ hex เปลี่ยนทุกครั้งที่เริ่มโปรแกรม ยาวไม่เกิน 64 ตัว ใช้ตัวอักษรอังกฤษ ตัวเลข `_` หรือ `-`
- `seq`: จำนวนเต็มบวกเพิ่มทุกข้อความ ภายใน session เดียวกัน ห้ามใช้เลขซ้ำ แม้ส่งท่าเดิม
- `gesture`: มี `NONE` และ `PARRY` เท่านั้น
- `active`: PARRY เป็น true, NONE เป็น false
- `confidence`: ความมั่นใจ 0–1 เกมรับท่าเมื่อ >=0.7 (ปรับหลังทดลองจริง)
- ไม่ส่ง timestamp เพราะ Bridge ใช้เวลาที่รับเพื่อกันนาฬิกาแต่ละเครื่องไม่ตรงกัน

ท่าเริ่มต้นที่เสนอคือยกแขนข้างว่างให้ข้อมือสูงกว่าไหล่ มืออีกข้างยังจับจอยได้ ให้เลือกแขนซ้าย/ขวาใน config ของโปรแกรมกล้อง ทดลอง hold ประมาณ 150–250 ms ก่อนเปลี่ยนเป็น PARRY เพื่อลดการสั่น (ปรับกับผู้เล่นจริง)

เมื่อลดแขนส่ง `NONE,false` และ confidence ตามการตรวจจับ; ไม่เห็นคนให้ส่ง `NONE,false,0` ต่อเนื่อง เกมจะแยกการเชื่อมต่อจากความมั่นใจ ไม่แสดงว่าเห็นคนทั้งที่กล้องหลุด

ลดแขนให้ตรวจพบก่อนแล้วค่อยยกเพื่อยิงครั้งใหม่ ค้างท่าไม่ยิงซ้ำ หลังเชื่อมใหม่/หยุดเกม/ตายก็ต้องลดแขนก่อน คูลดาวน์ 2 วินาที หากทำท่าระหว่างคูลดาวน์เกมจะไม่เก็บไว้ยิงภายหลัง

เกิน 500 ms โดยไม่มีข้อความใหม่ = pose หมดอายุ ไม่ใช้สกิล ข้อความซ้ำไม่ต่ออายุข้อมูล

## ให้ฝั่งเกมทดสอบก่อนมีกล้อง

ติดตั้ง Python `paho-mqtt` ใน virtualenv บน Pi หรือคอม จากนั้นตั้ง environment `CYBER_MQTT_HOST`, `CYBER_MQTT_PASSWORD` แล้วรัน `python tools/pose-simulator.py` ในโฟลเดอร์ CyberDiveBridge

พิมพ์ `n` Enter เพื่อลดแขน, `p` Enter เพื่อยกแขน, `q` Enter เพื่อออก โปรแกรมส่งซ้ำที่ 10 Hz แต่ seq ใหม่ทุกครั้ง กด p ค้างไม่ควรยิงรัว

## ฝั่งคอม

```powershell
cd CyberDiveBridge
npm.cmd ci
Copy-Item .env.example .env.local
```

แก้ `.env.local` ใส่ IPv4 ของคอมและรหัสส่วนตัว แล้วรัน `npm.cmd start` ต้องให้ Windows อนุญาต Node เฉพาะเครือข่าย Private ที่ใช้งาน

GET `http://127.0.0.1:8787/pose/latest` คืน `{valid,revision,sessionId,seq,gesture,active,confidence,ageMs}` ข้อมูลหมดอายุ active จะเป็น false และ gesture NONE

GET `http://127.0.0.1:8787/controller/latest` คืน `{valid,left,right,direction,ageMs}`; ESP32 ยังส่ง `catchlab/controller` CSV เดิม เช่น `1,0,0` ค่าจะหมดอายุหลัง 200 ms

HTTP เปิดเฉพาะคอมที่รันเกม ไม่ต้องให้ Pi เรียก HTTP และไม่ต้องเปิดพอร์ตออกอินเทอร์เน็ต

## เกณฑ์ต่อร่วมกัน

1. ESP32 คุมยานซ้ายขวา ขณะที่ Pi ส่งท่ากล้องเข้าเกมได้
2. ยกแขนค้างมีโล่ครั้งเดียว ลดแขนแล้วค่อยยกใหม่จึงใช้ซ้ำได้
3. ปิดโปรแกรม Pi เกิน 500 ms เกมต้องแสดง OFFLINE และไม่เปิดโล่เอง
4. เปิด Pi ใหม่โดยยกแขนอยู่ไม่ควรยิงเอง จนลดและยกอีกครั้ง
5. หน้าหยุดเกม/จบเกมไม่รับสกิล เก็บ log ความหน่วงจริงไว้ปรับจังหวะเตือนก่อนโจมตี
